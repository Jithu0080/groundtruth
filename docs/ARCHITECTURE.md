# ARCHITECTURE — Groundtruth

## 1. Shape

A single Python package with small CLI entry points. No server, no database server, no microservices. Data lives in versioned files. This is the simplest architecture that meets every PRD requirement.

```
corpus files ──ingest──▶ data/corpus/*.txt ──chunk──▶ chunks (doc_id,start,end)
                                                        │
                       config YAML ──build──▶ retriever (dense | bm25 | hybrid) [+ reranker]
                                                        │
golden_v1.jsonl ──queries──▶ evaluate ──▶ per-query CSV + summary JSON ──▶ compare (table + bootstrap CI)
                                  │
                                  └──top-5──▶ generate (LLM) ──▶ judge (faithfulness, relevance)

pytest regression test ◀── results/baseline.json        GitHub Actions runs pytest on every PR
```

## 2. Tech stack

| Choice | Why |
| --- | --- |
| Python 3.10+ (CI on 3.11) | Standard for ML tooling |
| sentence-transformers | Bi-encoder embeddings + CrossEncoder reranker in one library |
| NumPy exact search | Corpus is small; exact search keeps metrics free of ANN error |
| Own BM25 on scikit-learn sparse matrices | Vectorised and fast; avoids an extra dependency (`rank-bm25`) for ~30 lines of code |
| pandas | Per-category aggregation, result tables |
| PyYAML | Experiment configs |
| pypdf | PDF text extraction (ingest only) |
| Standard-library `urllib` for LLM calls | Two HTTP calls do not justify an SDK dependency |
| pytest + GitHub Actions | Regression gate |
| ruff + mypy | Lint/format and type checks |

## 4. Key design decisions

1. **Gold labels are character spans**, never chunk IDs, so chunking experiments don't invalidate the golden set.
2. **Hit rule:** a chunk matches a gold span when it covers ≥ 50% of the span. Each gold span counts once (overlapping chunks can't double-count).
3. **Experiments are configs**, never code edits.
4. **Dev/test split:** tune on dev, report on test.
5. **The gate is retrieval-only.** Generation eval is slow, paid and non-deterministic, so it runs on demand.
6. **Pluggable embedding backend.** `sentence-transformers` for real runs; a scikit-learn LSA backend exists only so tests and smoke runs work offline. LSA numbers are never reported as results.

## 5. Data flow details

- Chunk embeddings are cached at `.cache/embeddings/<model>_<chunk_size>_<overlap>_<corpus_hash>.npy`. The corpus hash invalidates the cache when the corpus changes.
- Retrieval for a query: first stage fetches `candidates` (default 50); reranker (if set) reorders to `k`; otherwise the first `k` are kept. Recall@candidates is recorded as the reranker's ceiling.

## 6. Database interaction

None. Files are the store (DATABASE.md). Future: pgvector or Qdrant HNSW when the corpus exceeds what fits in memory.

## 7. Authentication / authorization

None in the tool. Repository protection comes from GitHub branch protection. LLM provider keys are read from the environment.

## 8. External services

Hugging Face (model download), one LLM provider (generation eval only), GitHub Actions. All failures surface as clear errors; LLM calls use timeouts and bounded retries on 429/5xx only.

## 9. AI architecture

- Embedding: `BAAI/bge-small-en-v1.5` with its query instruction prefix, normalised vectors, cosine via dot product.
- Reranker: `cross-encoder/ms-marco-MiniLM-L-6-v2`.
- Generator: any chat model at temperature 0; grounded prompt with numbered sources.
- Judge: preferably a different model from the generator; calibrated against 20 hand labels.

## 10. Environment configuration

See `.env.example`. Variables: `GT_LLM_PROVIDER`, `GT_LLM_MODEL`, `GT_JUDGE_MODEL`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`. None are needed for retrieval or tests.

## 11. Error handling

Validation errors raise `GroundtruthError` with an actionable message; the CLI prints it and exits 1. Regression exits 2. Unexpected exceptions propagate with a traceback (no silent catch-all).

## 12. Security boundaries

- Corpus and golden files are data; never executed.
- Secrets only in the environment; `.env` is git-ignored; keys never logged.
- LLM output is parsed as JSON with validation, never evaluated.

## 13. Testing and deployment

- Unit tests: chunking, BM25, RRF, metrics (hand-computed worked example), golden validation, end-to-end smoke on a fixture corpus.
- Regression test: `configs/production.yaml` on `data/golden_v1.jsonl` test split vs `results/baseline.json`; skipped (not passed) when either is missing.
- Deployment = GitHub repo + Actions workflow + branch protection. No hosting.

## 14. MVP vs future

| MVP | Future |
| --- | --- |
| Exact NumPy search | HNSW index, with approximation loss measured |
| Character chunking | Paragraph/structure-aware chunking |
| Binary relevance | Graded relevance in nDCG |
| One corpus | Metadata filters (court, year), incremental indexing |
